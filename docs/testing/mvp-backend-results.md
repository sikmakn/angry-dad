# Проверки бэкенда MVP

Дата: 2026-10-24. Исходная ветка: `feat/mvp-api`; итоговая сборка: `codex/mvp-api-connect`.

## Результат

- Независимое ревью выявило семь дефектов; все исправлены после согласования с пользователем. Два повторных ревью соответствующих диффов не нашли замечаний. [Отчёт](../architecture/mvp/backend-review.md).
- Итоговый `npm test -w api`: **15 suites passed, 176 tests passed, 0 failed, 0 skipped**, exit 0. Node.js 22.17.0, Jest, ts-jest.
- Тесты написаны защищённой ролью `test-writer`. Из-за запрета доступа к Docker-сокету в её sandbox штатную команду выполнял родитель с разрешением; вывод передавался тестеру. Дополнительные временные сценарии родитель не создавал.
- Каждый прогон использовал собственный временный контейнер MongoDB через `scripts/testing/with-test-mongo.mjs`; итоговый раннер подтвердил удаление контейнера и данных. База хоста не использовалась.
- Telegram, Stars и AI подставные. В sharing проверялось создание настоящего PNG локально; отправка в реальный Telegram не выполнялась.

## Исправления тестовой инфраструктуры

ESM-only `@nestjs/event-emitter` не загружался прежней Jest-конфигурацией. В `apps/api/package.json` добавлена узкая CommonJS-трансформация JS только этой зависимости через установленный ts-jest; остальные `node_modules` не преобразуются. Обычная TypeScript-конфигурация сохранена, зависимости/глобальный Node/безопасный раннер не менялись. Отдельное независимое ревью этой правки не нашло дефектов.

В семи новых тестах ошибочно ожидался машинный код в `Problem.title`. Тестер сверил ожидания с контрактом: код находится в `type`, `title` содержит английский текст. Исправлены только ожидания и добавлены отсутствовавшие проверки `type`/`status`; остальные проверки сохранены. Продуктовая логика ради этих падений не менялась.

## Статический шлюз и стыковка

Первый общий шлюз в исходном API worktree останавливался на устаревших generated-типах фронтенда. После передачи решения оркестратору фронтенд адаптирован к фактическому Nest Swagger-контракту в `codex/mvp-api-connect`: алиасы enum берутся из полей DTO, типы пересобраны штатным генератором, добавлены два действия журнала, Vite сохраняет `/api`.

Финальные исходники API и все тесты перенесены в эту общую ветку. На объединённом результате повторно прошли **`npm run check` целиком**, **`npm run build` обоих приложений**, **176/176 backend-тестов** (15 наборов, временная MongoDB удалена) и **52/52 frontend-теста** (7 файлов). Lockfile сохраняет зависимости обеих сторон; исключений из шлюза нет.

Ранее на готовой стыковке прошли 7 браузерных сценариев с двойниками и отдельный Chromium → Vite → настоящий Nest → временная MongoDB smoke. При закрытии эти браузерные прогоны не повторялись: финальное обновление затронуло тесты и документацию API, runtime и контракт совпадают. Доказательства и границы — [отчёт стыковки](../web/api-integration.md). Пользователь явно одобрил общий коммит и локальное слияние в main 2026-10-24.

## Пределы

Этот набор не закрывает всю матрицу возможных сочетаний. Остаются отдельные гонки удаления во время внешней отправки, ошибки БД вокруг send, варианты восстановления аренд, расширенные когорты метрик, CAS summary и lifecycle/start-команды. Нагрузочные проверки и реальные Telegram/Stars/AI не проводились.

Потеря локальных событий статистики и двух новых записей журнала при сбое процесса допустима по D8/D10; тесты не требуют постоянной очереди или отката успешного действия при ошибке подписчика. В итоговом логе есть перехваченная `MongoRuntimeError` подписчика активности; Jest завершился успешно, неперехваченных отказов и упавших тестов не было. Гарантия доставки статистики этим прогоном не заявляется.
