# Запуск с настоящим ИИ

1. Подготовьте зависимости, MongoDB replica set и обязательную конфигурацию API по [инструкции](../api/setup.md). Для интерфейса нужен [web с реальным API](../web/setup.md); MSW не проверяет провайдера.
2. В окружении API и worker задайте `AI_API_KEY`. `EXTERNAL_CLIENTS_MODE` должен отличаться от `test`; значение `real` включает обычный режим. Этот переключатель относится и к другим внешним клиентам, включая Telegram.
3. По умолчанию используются Groq Chat Completions и модель `openai/gpt-oss-120b`. Для другого совместимого API задайте полный `AI_API_URL`, для общей модели - `AI_MODEL`. Отдельные цели переопределяются через `AI_MODEL_SPECIFICITY`, `AI_MODEL_JUDGE`, `AI_MODEL_ACTOR`, `AI_MODEL_SUMMARY`, `AI_MODEL_PARAPHRASE`.
4. Укажите тарифы каждой цели через `AI_<ЦЕЛЬ>_INPUT_USD_PER_MILLION` и `AI_<ЦЕЛЬ>_OUTPUT_USD_PER_MILLION`. Нулевые резервы модели по умолчанию не означают бесплатную работу. Подробности - [конфигурация](../api/config.md#денежная-оценка).
5. Из корня соберите API командой `npm run build -w api`, запустите `npm run start:dev -w api`, в другом терминале - `npm run start:worker -w api`. Оба процесса должны видеть одну конфигурацию. Nest читает `.env` относительно рабочего каталога процесса; при workspace-запуске это `apps/api`. Значения секретов в документацию и git не добавляются.

Для отдельной проверки выполните из корня `npm run ai:eval -w api`. Команда читает необязательный `apps/api/.env`, принудительно вызывает реальный ИИ и выполняет 100 запросов на 50 ходах. При доле неудачных ходов выше 10% возвращает ошибку. Она не требует запуска API/БД, но требует ключ и доступ к провайдеру; расходы оплачиваются у провайдера.

Команды сверены с package.json; сервер и eval в этом обновлении документации не запускались. Формат запросов, промпты и ограничения: [интеграция ИИ](../api/integrations/ai.md), [границы проверки](../limitations/ai-and-notifications.md).
