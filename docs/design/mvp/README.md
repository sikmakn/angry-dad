# Дизайн: Батя, MVP

## Финальная точечная передача · 2026-10-24

Новые состояния: task#edit-recurring, #edit-pool, #recurring-earlier, #rec-extended; battle#history-reply. Для Истории query `message` принимает только 12 ключей из `historySamples` в viewer.js: цитата и задача не читаются из произвольных данных. Для карточек query `sample` выбирает один из 14 результатов `shareSamples`, `battle` — один из восьми образцов `battleDegrees`; recovered сохраняет 50, answered — 43, norew — собственную финальную реплику. Это ограниченный набор статических примеров, а не хранение продуктового состояния. Название задачи при шеринге обезличивается; для боя до слома остаётся стартовая фраза согласно R-118. Без query карточки done/fail соответствуют done#medium/fail#normal. Сохранение формы названия демонстрирует возврат в ту же задачу; серверной записи в макете нет.

Вкладки владельца обрабатываются один раз; локальные data-go распознаются по существующим состояниям. Модальные окна запоминают инициатор и возвращают ему фокус; прямые ссылки берут безопасный маршрут из явной кнопки отмены, затем фокусируют h1. Поэтому owner#confirm-revoke по Escape возвращается в strikes, а не в изначально видимую phrases. Индекс и ссылки назад имеют минимум 44×44 по CSS. Во всех HTML версия viewer.js/tokens.css/base.css поднята до v=3; установленные родителем шрифты сохранены. Браузерные переходы, реальные размеры и поведение assistive technology нужно перепроверить родителю по QA.md. Новых вопросов и сценариев без экрана нет.

Интерфейс Telegram Mini App «Батя»: пользователь ставит задачу, получает давление от Бати или матери, закрывает или проваливает её, воюет в платном бою. Плюс раздел владельца. Начни с [index.html](index.html): список 14 экранов со ссылками на все состояния. Режим EDIT: сохранён существующий дизайн, исправлены D-1…D-10 финального [review.md](review.md). Первый отчёт с 42 решениями сохранён в [review-round-1.md](review-round-1.md). Статус: черновик, готов к предпросмотру, одобрение ещё не получено. Повторную браузерную QA выполняет родитель, эта роль её не проводила.

## Решения
| вопрос | решение |
|---|---|
| платформы | Telegram Mini App, телефон прежде всего (колонка до 440 px) |
| языки | русский, один язык |
| темы | светлая и тёмная, следуют теме Telegram/системы, переключатель в панели макета |
| визуальное направление | «Школьный дневник»: клетка, синие чернила, красная ручка, двойка в кружке и штамп «ЗАДАЧА ПРОВАЛЕНА»; тон токсично-ироничный, похвала скупая, без конфетти и эмодзи. Выбрано Никитой по двум вариантам экрана «Провал» |
| шрифты | PT Sans (текст) и Caveat (рукописные акценты, оценки, подпись Бати), оба с кириллицей; реальные локальные TTF и OFL в fonts/, URL в tokens.css, без Google @import |
| доступность | WCAG AA: контраст текста не ниже 4.5:1 (проверено по парам токенов), цели нажатия не меньше 44 px (в макете 48), видимый фокус, подписи полей, смысл не только цветом |
| навигация | нижнее меню: Главная, Бой, История, Рейтинг, Ещё (магазин, настройки, раздел владельца только для владельца) |

## Предпросмотр и передача

Открыть [index.html](index.html), выбрать экран, раскрыть «Состояния и варианты макета». Доступны все состояния, тема, родитель и пол независимо друг от друга. Выбор родителя/пола запоминается только для просмотра. Это не изменение профиля: старые сообщения в продукте остаются в прежней форме по R-13. Секции с явно обозначенной матерью/женским полом (`mother`, `phrases-mother`, `again-mother`) — закреплённые примеры; для четырёх независимых сочетаний использовать обычные состояния и общие переключатели.

Тема в Telegram берётся из `Telegram.WebApp.colorScheme`, обновляется по `themeChanged`. Вне Telegram — системная, ручной выбор панели позволяет проверить обе. SDK Telegram подключает приложение при реализации; статический HTML не делает сетевых запросов к API и не принимает платежи. Размер viewport — `100dvh`, safe-area есть у приложения, меню и поля боя.

Шторки унифицированы: `aria-modal`, именованные заголовки и описания, начальный фокус, цикл Tab, фон `inert`, меню скрыто. Escape и Telegram Back закрывают шторку; отдельные кнопки отмены возвращают к контексту. Панель просмотра находится за пределами интерфейса приложения и остаётся служебной.

Проверки названий в лимитных/аварийных текстах называются чтением названия. «Проверка» без уточнения — запрос прогресса. На системном старте сохранено «Вы» согласно R-2, R-3, N-1; персонаж и основное приложение обращаются на «ты». Это осознанное решение D-32 по первичным источникам.

В финальном проходе изменены README.md, QA.md, review.md (только колонка решений), copy.md, base.css, viewer.js, index.html и все 14 screens/*.html (в части экранов только версия ассетов). Новых файлов нет; tokens.css, fonts/ и review-round-1.md сохранены. Продуктовый код, ТЗ и контракт не изменялись. Коммит, слияние и публикация не выполнялись.

D-30 закрыт родителем: в fonts/ включены локальные TTF PT Sans 400/700 и Caveat 500/700 с лицензиями OFL. Проверена вся русская кириллица (включая Ё/ё); tokens.css использует локальные URL. Внешних запросов к Google Fonts нет. Рукописный характер направления сохраняется без установленных системных шрифтов.

Тексты юридических документов и username бота остаются входными данными владельца; новых вопросов для продолжения правок нет. Числа владельца/метрики и фразы — образцы. QA и итог шлюза фиксируются в [QA.md](QA.md); отсутствие браузерной проверки не означает прохождение WCAG.
