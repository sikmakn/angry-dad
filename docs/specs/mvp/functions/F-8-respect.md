# F-8 Шкала «Уважение»

**Кто:** пользователь · **Суть:** одна шкала от 0 до 100 (обычными событиями до 94, выше только сломом персонажа) показывает, насколько персонаж уважает пользователя; растёт за сделанное и удачные удары в бою, падает за провалы и молчание · [← ТЗ](../spec.md)

Изменения уважения:

| событие | изменение | источник |
|---|---|---|
| старт или повторный старт после удаления | значение 12 | source.md |
| «Готово» или «Сделано» в проверке (задача или период), по размеру задачи (R-134) | +1 микро, +3 средняя, +5 большая | A-23, D24 |
| ответ «Частично» или «Не начинал(а)» | 0 | A-29 |
| нет ответа на проверку 15 минут (не больше 1 на серию вместе с запустившей её проверкой, R-52) | −1 | A-29, A-63 |
| провал по дедлайну (задача или период) | −2 | A-29 |
| «Сдаюсь» | −1 | A-29 |
| продление, «Сделаю за час», удаление задачи, остановка повторяющейся задачи | 0 | A-29 |
| реплика боя с base ≥ 6 | от +0.5 до +2 по формуле R-102 | source.md, A-42 |
| слом персонажа с наградой (не чаще раза в 3 суток на роль) | +12, потолок 100 | D17, A-43 |

## Требования
| id | требование | критерий приёмки | сценарии |
|---|---|---|---|
| R-66 | Система ведёт одну шкалу уважения на пользователя (не зависит от роли) в диапазоне от 0 до 100 с шагом 0.5; стартовое значение 12; показывает целую часть с округлением вниз (A-28) | Когда уважение 13.5, тогда на экране «13» | [UC-44](#uc-44), [UC-45](#uc-45) |
| R-67 | Система меняет уважение только по таблице изменений | Когда пользователь закрывает среднюю задачу, тогда уважение растёт ровно на 3; микрозадачу — на 1; большую — на 5; когда отвечает «Частично», тогда не меняется | [UC-44](#uc-44), [UC-45](#uc-45), [UC-46](#uc-46), [UC-48](#uc-48) |
| R-68 | Система не поднимает уважение выше 94 никакими событиями, кроме слома персонажа (R-103); слом поднимает его не выше 100; значение выше 94, полученное сломом, другими прибавками не растёт и сохраняется, пока его не снизят штрафы; ниже 0 уважение не опускается; со временем не откатывается (D17) | Когда уважение 93 и задача закрыта, тогда уважение 94; когда уважение 92 и персонаж сломлен, тогда 100; когда уважение 98 и задача закрыта, тогда остаётся 98; когда уважение 0.5 и провал, тогда 0 | [UC-47](#uc-47) |
| R-69 | Система показывает уважение на главной странице, на экранах «Готово» (с изменением), «Провал» (с изменением) и «Бой» (A-28) | Когда пользователь закрывает задачу, тогда экран «Готово» по средней задаче показывает «Уважение: 15 (+3)» | [UC-19](F-4-one-time-task.md#uc-19), [UC-44](#uc-44) |

## Сценарии
Типы: основной, альтернативный, ошибка, граница, права, пустое состояние. Тип, который не применим, записан явно с причиной.

### UC-44
**Тип:** основной · **Роль:** пользователь · **Требования:** R-66, R-67, R-69, R-30
**Предусловия:** уважение 12.
**Шаги:**
1. Закрывает среднюю задачу (+3 → 15), не отвечает на проверку (−1 → 14), отвечает «Частично» (0 → 14), проваливает задачу (−2 → 12), нажимает «Сдаюсь» по другой (−1 → 11).
2. Ставит микрозадачу и через 5 минут нажимает «Готово» (+1 → 12); закрывает большую задачу (+5 → 17).
**Результат:** на главной «17»; на экранах «Готово» и «Провал» видно изменение (D24).

### UC-45
**Тип:** альтернативный · **Роль:** пользователь · **Требования:** R-67, R-102, R-66
**Шаги:**
1. В бою реплика с base 8 (+1), затем с base 6 (+0.5), затем с base 5 (0).
**Результат:** уважение выросло на 1.5, на экране целая часть (например, 11.5 показано как «11»).

### UC-46
**Тип:** ошибка · **Роль:** пользователь · **Требования:** R-94, R-67
**Что идёт не так:** ход боя с base 9 завершился ошибкой актёра.
**Поведение:** уважение не изменилось, удар возвращён.

### UC-47
**Тип:** граница · **Роль:** пользователь · **Требования:** R-68
**Шаги и результат:**
1. Уважение 93, средняя задача закрыта — 94; ещё одна — остаётся 94; слом персонажа — 100; ещё задача — остаётся 100; провал — 98.
2. Уважение 0.5, провал — 0; ещё провал — остаётся 0.
3. Неделя без событий — уважение не изменилось.

### UC-48
**Тип:** права · **Роль:** пользователь, владелец · **Требования:** R-67, N-10
**Шаги:**
1. Пользователь пытается изменить уважение запросом в обход действий.
2. Владелец ищет функцию изменения уважения.
**Результат:** запрос отклонён; у владельца функции изменения уважения нет — уважение меняется только по таблице событий.

### Пустое состояние
Не применимо: шкала существует с момента старта и всегда имеет значение (12 на старте).
