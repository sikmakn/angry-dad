# F-11 Диалог боя

**Кто:** пользователь · **Суть:** по «Ответить» пользователь попадает в диалог с персонажем, один на каждую роль, с полной историей и платными репликами · [← ТЗ](../spec.md)

## Требования
| id | требование | критерий приёмки | сценарии |
|---|---|---|---|
| R-86 | Система ведёт один диалог боя на пару «пользователь, роль» (D5) и показывает на странице «Бой»: историю диалога, поле реплики до 300 символов, шкалы «Уважение» и «Побеждённость» (D15), баланс ударов, кнопку покупки ударов | Когда пользователь открывает «Бой», тогда видит все элементы, а диалог содержит все прошлые реплики с текущей ролью | [UC-60](#uc-60), [UC-64](#uc-64) |
| R-87 | Система по «Ответить» на сообщении персонажа (в боте, в «Истории», на экране «Провал») открывает страницу «Бой» и добавляет это сообщение в диалог как реплику персонажа вместе с названием задачи, к которой оно относится (решение C-23) | Когда пользователь нажимает «Ответить» под проверкой задачи «написать отчёт», тогда в конце диалога видна эта проверка с пометкой задачи, а прежняя история сохранена | [UC-60](#uc-60), [UC-61](#uc-61) |
| R-88 | Система открывает страницу «Бой» и из меню Mini App, без добавления сообщения; диалог продолжается с последней реплики (A-35) | Когда пользователь открывает «Бой» из меню, тогда диалог тот же, новых реплик персонажа не добавлено | [UC-61](#uc-61) |
| R-89 | Система передаёт актёру сжатое изложение ранних реплик и все несжатые реплики, но не меньше последних 8; когда несжатая часть больше 20 реплик, всё, кроме последних 8, сжимается в изложение; пользователь всегда видит полную историю (D5, A-36, A-73) | Когда в диалоге 40 реплик, тогда пользователь листает все 40, а актёр получает изложение реплик 1–26 и реплики 27–40 полностью | [UC-60](#uc-60), [UC-63](#uc-63) |
| R-90 | Система при нулевом балансе ударов оставляет поле реплики доступным, заменяет кнопку отправки на «Купить удары» и сохраняет введённый текст до покупки | Когда баланс 0 и пользователь ввёл реплику, тогда вместо «Отправить» видна «Купить удары»; после покупки текст в поле сохранён | [UC-62](#uc-62), [UC-73](F-13-payments.md#uc-73) |
| R-91 | Система при открытии пустого диалога показывает первую реплику персонажа из категории onBattleStart (A-35) | Когда пользователь впервые открывает «Бой» с матерью из меню, тогда видит одну фразу onBattleStart от матери | [UC-65](#uc-65) |
| R-92 | Система не меняет статус задачи из-за боя или слома (A-37) | Когда пользователь сломал персонажа, ответив на onFail, тогда задача остаётся failed | [UC-63](#uc-63) |
| R-93 | Система не отправляет реплику короче 2 непробельных символов и не даёт ввести больше 300 символов; удар за такую попытку не списывается (A-38) | Когда пользователь отправляет «.», тогда кнопка отправки неактивна и баланс не меняется | [UC-62](#uc-62), [UC-63](#uc-63) |

## Сценарии
Типы: основной, альтернативный, ошибка, граница, права, пустое состояние. Тип, который не применим, записан явно с причиной.

### UC-60
**Тип:** основной · **Роль:** пользователь · **Требования:** R-86, R-87, R-89
**Предусловия:** у пользователя 5 ударов, диалог с отцом уже был.
**Шаги:**
1. Под проверкой задачи «написать отчёт» нажимает «Ответить».
2. Открывается «Бой».
**Результат:** в конце диалога проверка с пометкой задачи, прежняя история на месте, видны шкалы, баланс 5, поле реплики.

### UC-61
**Тип:** альтернативный · **Роль:** пользователь · **Требования:** R-88, R-87
**Шаги:**
1. Открывает «Бой» из меню Mini App.
2. Позже нажимает «Ответить» на экране «Провал».
**Результат:** в первом случае новых реплик персонажа нет, диалог продолжается; во втором фраза провала добавлена в диалог.

### UC-62
**Тип:** ошибка · **Роль:** пользователь · **Требования:** R-90, R-93
**Что идёт не так:** 1) баланс 0, пользователь ввёл реплику; 2) реплика «.».
**Поведение:** 1) вместо «Отправить» — «Купить удары», текст сохранён до и после покупки; 2) кнопка отправки неактивна, удар не списан.

### UC-63
**Тип:** граница · **Роль:** пользователь · **Требования:** R-89, R-93, R-92
**Шаги и результат:**
1. Реплика 300 символов отправляется; 301-й символ не вводится.
2. В диалоге 40 реплик: пользователь листает все 40, актёр получает изложение реплик 1–26 и реплики 27–40 полностью (A-73).
3. Пользователь сломал персонажа, отвечая на onFail проваленной задачи — задача остаётся failed.

### UC-64
**Тип:** права · **Роль:** пользователь · **Требования:** R-86, R-12, N-10
**Шаги:**
1. Пользователь пытается открыть диалог другого пользователя.
2. Меняет роль на мать.
**Результат:** доступа к чужому диалогу нет; «Бой» показывает диалог с матерью, диалог с отцом скрыт, но сохранён.

### UC-65
**Тип:** пустое состояние · **Роль:** пользователь · **Требования:** R-91
**Предусловия:** с текущей ролью боя не было.
**Шаги:**
1. Открывает «Бой» из меню.
**Результат:** одна реплика персонажа из onBattleStart, побеждённость 0, поле реплики.
