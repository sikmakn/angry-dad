# Вход, ошибки и повторы

## Авторизация

Пользовательские запросы идут под `/api` с `Authorization: tma <initData>` — исходной подписанной строкой запуска Telegram Mini App. Собственных access/refresh-токенов нет. Проверяются HMAC, уникальность параметров, безопасный положительный Telegram ID и возраст `auth_date`. Источник: [TelegramAuthService](../../apps/api/src/modules/users/services/telegram-auth.service.ts).

`GET /me` позволяет узнать состояние профиля; `POST /me/onboarding` завершает старт. Для основных действий требуется завершённый onboarding. Owner-операции дополнительно сверяют Telegram ID с `OWNER_TELEGRAM_ID`; владелец не получает доступ к чужим задачам и диалогам. Права и параметры конкретного запроса описаны в [OpenAPI](../openapi.yaml).

Вебхук `POST /api/telegram/webhook` использует `X-Telegram-Bot-Api-Secret-Token`, а не Mini App Authorization. Кнопки дополнительно проверяют пользователя и принадлежность записи. См. [Bot](modules/bot.md).

## Форма ошибки

Ошибки возвращаются как `application/problem+json`: `type` с машинным кодом в URI `urn:angry-dad:problem:<code>`, `title` с английским текстом и `status` с HTTP-статусом. Нельзя сравнивать `title` с машинным кодом. Дополнительные `reply`, `errors`, `periodStatus` зависят от операции; их форму нужно брать из контракта.

Глобальная валидация преобразует DTO и запрещает неизвестные поля. Неожиданные исключения скрываются за 500 `internal_error`. Источники: [AppModule](../../apps/api/src/app.module.ts), [фильтр](../../apps/api/src/common/filters/all-exceptions.filter.ts), [Problem DTO](../../apps/api/src/openapi/problem.dto.ts).

Практические реакции клиента:

- 400 `validation_failed` — исправить ввод по схеме; `task_vague` может содержать реакцию персонажа, задача не создана.
- 401 `unauthorized` / `init_data_expired` — получить актуальные подписанные данные запуска.
- 403 `onboarding_required` / `owner_only` — завершить старт либо прекратить недоступное действие.
- 404 — ресурс не найден или недоступен этому пользователю.
- 409 — перечитать актуальное состояние; например, `role_mismatch`, `turn_in_progress`, `idempotency_key_reused`. Просроченный период тоже нельзя успешно закрыть только потому, что worker ещё не обработал дедлайн.
- 429 — достигнут прикладной лимит; 502/503 — временный отказ соответствующей операции. Автоповтор зависит от гарантий ниже.

Это ориентиры, не полный перечень кодов: допустимые статусы каждой операции находятся в OpenAPI.

## Ключи повторов

`Idempotency-Key` обязателен для хода боя. Повтор успешного хода возвращает прежнее тело, выполняющегося — конфликт, неуспешного — прежнюю ошибку; новая попытка требует нового ключа. Другой текст с прежним ключом запрещён.

Для создания счёта, ручной операции ударов и цитаты ключ необязателен. У финансовых ключей срок 24 часа; у цитаты — пока хранится реплика. Повтор счёта с другим пакетом или цитаты с другим сообщением даёт 409. Первое создание и повтор могут отличаться статусом 201/200 и заголовком `Location` согласно конкретной операции.

`POST /tasks` ключа не имеет: каждый успешный вызов создаёт отдельную задачу. После сетевого таймаута нельзя считать слепой повтор безопасным — сначала перечитайте список задач. Защита платежного подтверждения по charge ID действует независимо от необязательного ключа создания счёта. Источник: [фактический контракт и D3/D9](../architecture/mvp/api-contract.md#исправленные-повторы-и-конфликты).

Курсоры списков непрозрачны: передавайте полученный `nextCursor` без самостоятельного разбора или склейки; `null` означает конец списка.
