# Payments

Пользователь получает доступные пакеты и создаёт счёт через `POST /packages/{packageId}/invoices`. Счёт сохраняет снимок пакета, payload и курс. Необязательный ключ повтора продолжает тот же счёт даже после ошибки получения ссылки; повтор с другим пакетом запрещён. Аренда с токеном защищает запись ссылки от запоздалого владельца.

`pre_checkout_query` проверяется и закрепляется до ответа Telegram, но одобрение ещё не является оплатой. `successful_payment` проверяет payload, пользователя, валюту, сумму и charge ID. Условный переход и начисление партии ударов фиксируются одной Mongo-транзакцией, без внешнего запроса внутри неё. Обычно `invoiced` переходит сразу в `credited`; `paid` остаётся для восстановления прежних записей и подтверждённых оплат, которые нельзя зачислить удалённому пользователю.

Webhook, дозачисление и сверка используют один путь подтверждения. Worker отдельно, при старте и раз в минуту, ищет ожидающие счета старше пяти минут и сверяет историю Stars с продолжением страниц. Отсутствие записи не означает отмену оплаты. Несовпадения и найденные возвраты сохраняются в PaymentIncident для разбирательства, без повторного начисления и без нового автоматического возврата.

Владелец управляет пакетами, просматривает платежи и обращения `/paysupport`, делает возврат целого платежа с причиной. Возврат разрешён для `credited`, пока пользователь существует и вся исходная партия не израсходована (`remaining == total`); повтор уже возвращённого платежа отдаёт его состояние. Недопустимый возврат даёт 409, ошибка внешнего шлюза — 503.

При фактической смене статуса обращения публикуется `support_ticket_status_changed`; повтор текущего статуса событие не создаёт. Доставка именно этой записи журнала best-effort, финансовая защита остаётся транзакционной.
