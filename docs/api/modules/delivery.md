# Delivery и лента

Модуль исполняет отправку outbox и обслуживает `GET /feed`, `PUT /feed/{feedMessageId}/read`, `PUT /feed/{feedMessageId}/rating`, `PUT /feed/{feedMessageId}/check-in-answer`. Подготовленный черновик не является доставленным сообщением и скрыт из пользовательской истории до подтверждения отправки.

`GET /feed` ставит проверки, ожидающие ответа, перед остальными записями, независимо от прочтения. Приоритет применяется до пагинации: сначала ближайший общий срок группы, затем `_id` по убыванию. Курсор учитывает приоритет, срок и идентификатор записи.

Ответ на проверку в одной транзакции закрывает остальные доставленные проверки того же пользователя и периода задачи: `checkIn.resolvedAt` и `readAt`, без синтетического `answer` и без изменения уважения. Они исключаются из ожидающих ответа и обработки штрафов за молчание. Уже начисленные штрафы не пересчитываются, новые проверки не закрываются заранее. Для «Не начинал(а)» используется отдельный язвительный пул `on_check_in_reply`, уровень 2; уровень 1 для «Частично» остаётся прежним.

При пропуске 15-минутного окна ответа worker сохраняет `checkIn.respectDelta` — фактическое изменение уважения. Повторное сообщение серии не получает повторного списания; дневной лимит и нижняя граница уважения отражаются нулём. Для старых проверок с `missedAt` собственный штраф восстанавливается при чтении из журнала `RespectChange`, без изменения истории и повторного начисления.

Текущая группа — доставленные проверки одного периода без `answer` / `resolvedAt`. Отсчёт начинается с первой проверки группы и не сбрасывается чтением или последующей доставкой. По истечении 15 минут worker отмечает всю группу просроченной и применяет не больше одного штрафа; поздние уведомления той же группы не создают новых списаний. `nextAnswerDueAt` — ближайший общий срок среди активных групп. `checkIn.answerDueAt` — общий срок карточки, `expired` — просрочка всей группы, `groupRespectDelta` — сумма реальных списаний, только для верхней карточки группы. `taskOutcome` отражает выполненный/сданный/проваленный период для всех связанных записей.

`readAt` хранит первое открытие сообщения пользователем. Метод read проверяет владельца и видимость сообщения, идемпотентен и не отвечает на проверку. Ответ на проверку также отмечает сообщение прочитанным. `needsAnswer` вычисляется по состоянию связанного текущего периода и задачи, а не только по отсутствию `checkIn.answer`.

`GET /feed` возвращает глобальные счётчики пользователя, независимо от курсора и фильтра страницы: `unreadCount` — непрочитанные уведомления категорий on_reminder, on_check_in, on_check_in_missed, on_fail, on_absent; `unansweredCount` — проверки активных, не просроченных задач без ответа; `activeCount` — объединение этих групп без повторного счёта. Обычные записи дневника (например, ответ о выполнении задачи), черновики и недоставленные проверки не увеличивают счётчик; закрытая задача не оставляет активных запросов ответа.

Dispatcher берёт записи в аренду, проверяет актуальность общего плана пользователя и отправляет через Telegram вне Mongo-транзакции. Выбор фразы и состояние персонажа относятся к моменту отправки. Успех фиксирует факт доставки; сетевой отказ, неизвестный исход и запоздалый результат обрабатываются по-разному. Аренда Mongo не превращает внешний Bot API в exactly-once транспорт.

Текст Telegram оформляется отдельно от снимка feed: жирная метка типа с цветным маркером (жёлтый — проверка, оранжевый — напоминание, красный — пропуск/провал, синий — отсутствие), курсивная подпись родителя, отдельным абзацем жирное название задачи, затем реплика в блоке цитаты. Цвет фона и полосы цитаты выбирает Telegram. Пользовательский текст и фраза экранируются для HTML; обычные ответы бота продолжают отправляться без parse_mode. Старые снимки с префиксом «Про …» отображаются без повторного названия.

Ответ check-in проверяет владение, состояние сообщения и периода. «Сделано» использует переход задачи; другие допустимые ответы возвращают готовый `reply`. Бот отправляет этот ответ и подтверждает callback, не выполняя повторно бизнес-переход.

Новые уведомления содержат одну кнопку «Открыть приложение» с `web_app` URL `?notification=<feedId>`, который фронтенд преобразует в страницу `#notification/<feedId>`. Ответы на проверку и действия задачи выполняются внутри приложения. Под оцениваемой фразой остаются только три реакции 😐 / 😞 / 😭 (score 0 / 1 / 2). Успешный callback оценки показывает реплику персонажа о частоте фразы через Telegram callback notification, без нового сообщения в чат. Старые callback-кнопки остаются совместимыми.

При расследовании отличайте сохранённый план, outbox draft и подтверждённый feed. Отсутствие сообщения в ленте не доказывает отсутствие сетевой попытки. Для редких гонок удаления и ошибок БД вокруг отправки остаются [пределы тестов](../../testing/mvp-backend-results.md#пределы).
