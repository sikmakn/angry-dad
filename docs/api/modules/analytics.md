# Analytics, настройки и журнал

Owner API предоставляет метрики за период, журнал и GameSettings. Настройки управляют игровыми коэффициентами, квотой AI и выбором фраз без выпуска новой версии; операции требуют owner-доступа. Схемы запросов и полный перечень настроек — в [OpenAPI](../../openapi.yaml).

Первый старт — первый `/start`, открытие через `GET /me` либо допустимая пользовательская мутация. Первое создание задачи публикуется только после её коммита. UserStatistics и UserActivityDay обновляются асинхронным локальным подписчиком; операционный `User.lastActivityAt` сохраняется синхронно. Редкая потеря статистики при падении процесса допустима D8, восстановления очередью нет. Сразу после действия метрика может ещё не измениться.

D7 означает возврат именно в седьмой календарный день UTC, только для зрелой когорты. Дневная активность не является журналом посещений с точностью до часа. Отсутствие знаменателя даёт `null`, известный нулевой результат — `0`. Проверки считаются по подтверждённым отправкам, без drafts. Метрика share означает подготовку карточки, а не доказанную пересылку.

Денежная метрика использует платные израсходованные удары и расходы всех относящихся к ним попыток. Неизвестная/подставная стоимость, незавершённый резерв и отсутствие достоверной выручки дают `null`. История не пересчитывается по сегодняшним тарифам. Формулы и границы: [аналитика D7/D8](../../architecture/mvp/analytics.md).

По D10 события журнала `paraphrase_generate` и `support_ticket_status_changed` тоже асинхронные и best-effort. Их потеря не откатывает успешную операцию; это не ослабляет прежние денежные транзакции. Журнал не следует использовать как гарантированную очередь финансовой сверки.
