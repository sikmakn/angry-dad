# Bot и входящие updates

Вебхук `POST /api/telegram/webhook` проверяет секретный заголовок и допустимый `update_id` до обработки. HTTP API принимает команды `/start`, `/terms`, `/paysupport`, кнопки, платёжные updates и изменения блокировки бота. Пользовательская логика делегируется профильным модулям.

Mongo-запись TelegramUpdateReceipt с ключом `botId:updateId` хранит завершение между экземплярами API. Завершённый повтор подтверждается без повторного запуска обработчика. Незавершённый update захватывается с арендой и продлением; после сбоя обработка может повториться. Завершённые записи удаляются TTL через 48 часов. Это ограниченная дедупликация, не вечный журнал Telegram.

Кнопки проверяют отправителя и владельца записи; пересылка сообщения не даёт права изменить чужую задачу. Для ответа проверки бот отправляет готовый `reply`, затем подтверждает callback. `/paysupport` использует стабильный ID источника: повтор после сбоя подтверждения не создаёт второе обращение.

Внешние отправки Telegram не входят в Mongo-транзакцию. Повтор updates и потеря сетевого ответа требуют отдельных защит модулей, в частности charge ID платежа. Автоматическая регистрация публичного вебхука не подтверждена этим шагом документации: оператор должен отдельно настроить Telegram на доступный HTTPS endpoint и согласованный секрет.
