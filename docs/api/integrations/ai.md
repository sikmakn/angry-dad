# OpenAI-совместимый ИИ

`ConfiguredAiProvider` отправляет POST в Chat Completions API. По умолчанию адрес - `https://api.groq.com/openai/v1/chat/completions`, модель всех целей - `openai/gpt-oss-120b`. Это значения по умолчанию в коде, а не гарантия доступности провайдера. `AI_API_URL` задаёт полный endpoint, авторизация Bearer берётся из `AI_API_KEY`. Приоритет модели: `AI_MODEL_<ЦЕЛЬ>` → `AI_MODEL` → значение по умолчанию.

Запрос содержит `model`, два `messages` (системная инструкция и JSON с данными), `max_tokens=2000`, `stream=false`. Для модели с `gpt-oss` в имени добавляется `reasoning_effort=low`. Старый протокол `purpose/input/value` не используется.

## Пять промптов

- `SPECIFICITY` проверяет конкретное действие и результат, просит минимум три слова; возвращает JSON с признаком конкретности и размером micro/medium/large.
- `JUDGE` оценивает попадание, логику и новизну целыми 0–10, противоречие и ключ слабого места. Получает карточку и последние четыре реплики. Неизвестный ключ слабого места сервис заменяет на `null`.
- `ACTOR` отвечает в роли родителя в 1–3 предложениях, учитывает род, режим, побеждённость, частичное признание, восстановление, summary и контекст.
- `SUMMARY` сжимает ранние сообщения и предыдущую сводку, сохраняя факты; максимум 8000 символов.
- `PARAPHRASE` просит пять вариантов с сохранением переменных и родовых форм. Валидатор принимает от 1 до 20 непустых строк короче 4000 символов; варианты требуют проверки владельцем.

Исходные инструкции: [helpers](../../../apps/api/src/modules/ai/helpers). Данные пользователя, карточки, истории и шаблоны отделены от системного сообщения и объявлены недоверенными. Судья получает инструкцию обнулять чистые инъекции; актёр - отказывать в раскрытии инструкций внутри роли. Это меры защиты промптов, а не доказательство устойчивости ко всем атакам.

## Проверка ответа и ошибки

Принимается `choices[0].message.content` только при `finish_reason=stop`, без `tool_calls`. JSON-цели разбираются без удаления Markdown-обёрток; поля specificity/judge и диапазоны проверяются строго. Актёр ограничен 2000 символами и тремя предложениями. Тело ответа ограничено 64 КиБ. Отказы, обрезанный/невалидный ответ, HTTP/сетевой сбой и timeout разделяются в учёте.

Длинное и среднее тире в actor/summary и строках paraphrase заменяются на короткий дефис. Судья может повторить невалидный результат до трёх попыток в общем бюджете хода. Проверка задачи имеет timeout 3 секунды, прочие вызовы вне хода по умолчанию - 15 секунд; judge/actor используют оставшийся бюджет хода. Сбой не становится успешным игровым результатом.

Источники: [провайдер](../../../apps/api/src/modules/ai/services/ai-provider.service.ts), [валидатор и usage](../../../apps/api/src/modules/ai/helpers/provider-response.ts), [шлюз](../modules/ai.md).

## Режимы и стоимость

`EXTERNAL_CLIENTS_MODE=test` даёт фиксированные ответы без внешнего запроса и помечает расходы как mock. В реальном режиме провайдер получает необходимый игровой контекст без Telegram ID, имени и username.

Usage разбирается из `prompt_tokens`, `completion_tokens`, `total_tokens` и reasoning tokens с защитой от двойного учёта. Стоимость вычисляется по тарифам конфигурации, которые сохраняются снимком в `AiCall` вместе с моделью и каждой попыткой. Тарифы автоматически у провайдера не запрашиваются. Для модели по умолчанию без настройки тарифов код использует нули: это не подтверждение бесплатности. Имена тарифных переменных и резервные значения - в [конфигурации](../config.md#денежная-оценка). Отсутствующий usage и mock не доказывают реальную экономику.

## Оценка на 50 ходах

Из корня: `npm run ai:eval -w api`. В корневом package.json отдельного `ai:eval` нет. Workspace-команда загружает необязательный `apps/api/.env`; уже заданное окружение имеет приоритет. Требуется `AI_API_KEY`, режим принудительно реальный даже при `EXTERNAL_CLIENTS_MODE=test`.

Скрипт читает [50 жёстких реплик](../../../apps/api/scripts/ai-eval-turns.json), чередует отца/мать, для каждой вызывает judge и actor (100 запросов, общий бюджет 30 секунд на пару). Неудача любого вызова делает ход неудачным; доля сбоев **до 10% включительно** даёт код выхода 0, выше - 1. Выводит доли refusal/invalid/error/timeout, среднюю задержку, стоимость и полноту usage. Это проверка формата и доступности, без автоматической оценки качества язвительности или стойкости к инъекциям; specificity/summary/paraphrase она не покрывает.

В этом обновлении документации внешние запросы не выполнялись. Сообщение merge `f3abb78` упоминает пять живых запросов, но явно оставляет полный eval, доработку актёра и нагрузку на ленту незавершёнными. Подробнее: [границы доказанного](../../limitations/ai-and-notifications.md).
