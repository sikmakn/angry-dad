# AI gateway

ConfiguredAiProvider отправляет POST с моделью, назначением `purpose`, объектом `input` и лимитом вывода; авторизация — Bearer из `AI_API_KEY`. Ожидается адаптер с ответом `value` и доступными usage/стоимостью, а не произвольный endpoint любого провайдера. При необходимости адаптации его протокола это отдельная работа.

Потребители валидируют тип и содержимое результата: конкретность/размер, структуру судьи, длину ответа актёра, summary и массив перефразов. Сетевая успешность сама по себе не означает валидный игровой результат. Судья может повторять невалидные ответы в пределах бюджета; каждая попытка учитывается отдельно.

Настройки выбирают SMART/FAST и модели отдельных задач, но не доказывают доступность модели или её актуальную цену. Цены берутся из конфигурации и сохраняются снимком, без автоматического запроса тарифов. Неизвестные и mock расходы не подменяют достоверную экономику боя.

Провайдер получает только необходимый игровой контекст, без Telegram ID/имени/username. Тесты использовали подставные ответы, отказы, таймауты и некорректные структуры; качество живого актёра, доля отказов и расходы реального провайдера не проверялись. Живой AI пользователь отложил.
