# Запуск и разработка API

Все команды ниже выполняются из корня репозитория. Они сверены с [корневым package.json](../../package.json) и [workspace API](../../apps/api/package.json); в шаге документации команды не запускались.

## Окружение

Нужны Node.js и npm с workspaces, установленные зависимости и MongoDB replica set с доступным primary. Транзакции обязательны для задач, финансов и боя; standalone MongoDB недостаточно. Итоговые тесты прошли на Node.js 22.17.0: глобальный переход на Node.js 24 не требуется.

Для обычного запуска задайте [конфигурацию](config.md) в окружении обоих процессов. Nest Config читает `.env` относительно рабочего каталога, кроме тестового режима и экспорта OpenAPI. Если запускаете npm из другого каталога, проверьте доступность конфигурации в нём. Реальные секреты в репозиторий не добавляйте.

При инициализации базы [seed](../../apps/api/src/database/seed.service.ts) добавляет отсутствующие пакеты, карточки ролей и фразы по стабильным ID. Изменения владельца сохраняются благодаря `$setOnInsert`. Это запись в подключённую БД при запуске, а не отдельная команда миграции.

## Два процесса

Сборка API:

```sh
npm run build -w api
```

HTTP API в разработке:

```sh
npm run start:dev -w api
```

В отдельном терминале worker из собранного кода:

```sh
npm run start:worker -w api
```

Worker не следит за исходниками: после правок его нужно пересобрать и перезапустить. Для HTTP из сборки используется `npm run start:prod -w api`. API обслуживает маршруты под `/api`; worker не открывает HTTP-порт. Оба процесса должны видеть одну БД и согласованную конфигурацию.

Без worker не исполняются расписание, отправка outbox, обработка дедлайнов, восстановление ходов, дозачисление и сжатие диалогов. Обычный цикл worker последовательно запускает задания примерно раз в секунду без перекрытия собственного цикла; ошибки задания логируются, следующие задания продолжаются. Сверка платежей работает отдельно при старте и раз в минуту. При остановке worker ожидает начатые задания. Источник: [WorkerModule](../../apps/api/src/worker.module.ts).

## Контракт и Swagger

Источником HTTP-контракта служат контроллеры, DTO и Swagger-метаданные в коде. YAML/JSON вручную не исправляются.

```sh
npm run generate:openapi
npm run check:openapi
npm run docs:api
```

Первая команда собирает и экспортирует контракт без запуска приложения, MongoDB, загрузки `.env` и внешних клиентов. Вторая сверяет сохранённые артефакты без записи. Третья открывает отдельный локальный Swagger UI на `http://localhost:4010`, читая сохранённый YAML; она не запускает API и не генерирует контракт.

`start`, `start:dev`, `start:debug` автоматически выполняют экспорт один раз перед запуском. Ошибка экспорта останавливает запуск. Отдельный watch-rebuild экспорт не повторяет: после изменения DTO/маршрутов выполните отдельную генерацию. `build`, `start:prod` и `start:worker` автоэкспорта не делают. Подробности: [D9/D10 и экспорт](../architecture/mvp/api-contract.md).

Генерация frontend-типов — отдельная команда `npm run generate:api`; она не входит в экспорт и не означает адаптацию клиента. Текущий блокер описан в [ограничениях](../limitations/backend.md).

## Тесты и шлюз

```sh
npm test -w api
npm run check
```

Тестовая команда использует [безопасный раннер](../../scripts/testing/with-test-mongo.mjs): требуется работающий Docker и доступ к его сокету. Раннер создаёт собственный временный MongoDB replica set, ограничивает права приложения и удаляет контейнер с данными. Перехода на базу хоста при ошибке нет. Есть workspace-команды `test:watch`, `test:cov`, `test:debug` с тем же раннером.

Jest преобразует ESM `@nestjs/event-emitter` через узкую настройку ts-jest; остальные зависимости не переводятся целиком в другой режим. Не добавляйте ради этого глобальные флаги Node.

По [итоговому отчёту](../testing/mvp-backend-results.md): 15 suites, 176 tests passed, без failed/skipped; живые Telegram/Stars/AI не вызывались. Это не полное покрытие исходной матрицы. Общий `npm run check` сейчас останавливается на `check:api` после успешного `check:openapi`; интеграция и деплой не подтверждены.
