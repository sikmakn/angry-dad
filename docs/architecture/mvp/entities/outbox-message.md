# OutboxMessage · [← сводка](../00-overview.md)

Запланированное сообщение персонажа; диспетчер отправляет его или отменяет.

> Актуальная модель по D6 — [единое расписание пользователя](../task-notifications.md). Поля ниже сохраняются, но прежние правила независимого планирования и отброса по исходному времени заменены проверкой актуальности единственного плана. Новые поля и переходы перечислены в конце страницы.

**Связи:** → User, Period
**Сценарии:** UC-32…UC-43 ([привязка](../use-cases.md))
**Модуль-владелец:** [delivery](../modules.md#delivery) (исполняет), pressure (планирует)

## Поля
| поле | тип | обязательное | откуда значение | кто пишет | в API |
|---|---|---|---|---|---|
| `id` | id | да | генерируется | система | нигде |
| `userId`, `periodId` | ref | да / нет | вычисляется | pressure | нигде |
| `kind` | enum(check_in, series_check_in, reminder, fail, absent, check_in_missed) | да | вычисляется | pressure | нигде |
| `priority` | int | да | вычисляется (просрочка > напоминание > onAbsent > проверка) | pressure | нигде |
| `dueAt` | date | да | вычисляется | pressure, delivery (сдвиг) | нигде |
| `originalDueAt` | date | да | копия-снимок dueAt (сдвиг больше 15 мин отменяет) | pressure | нигде |
| `status` | enum(planned, leased, sent, cancelled, dropped) | да | вычисляется | delivery | нигде |
| `leaseUntil` | date | нет | вычисляется (аренда воркером) | delivery | нигде |
| `dedupeKey` | string | да | вычисляется (слияние одного типа по задаче) | pressure | нигде |

«В API»: владельцу — хозяину записи; админу — владельцу продукта.

## Инварианты
- одна запись с данным dedupeKey в статусе planned
- отправка не раньше lastSentAt + 3 мин

## Статусы и переходы
| из | событие | в |
|---|---|---|
| — | планирование | planned |
| planned | воркер взял в аренду | leased |
| leased | отправлено | sent |
| planned, leased | закрытие задачи, тихие часы для проверки, сдвиг > 15 мин | cancelled |
| planned | опоздание > 15 мин (кроме первого onFail) | dropped |
| leased | аренда истекла | planned |

## Уточнение D6

Владелец планирования — `task-notifications`, исполнение — `delivery`. `planRevision` связан с состоянием пользователя; для пары `userId + planRevision` есть уникальный индекс. Legacy planned/leased записи без ревизии отменяются.

Успешная запись — одновременно факт истории: `sentAt`, `primaryTaskId`, `secondaryTaskId`/`secondaryPeriodId`, `reason`/`reasonAt`, `sourceFeedId`, `intensity`, `role`, `contextKey`, `seriesId`/`seriesOriginFeedId` и `feedMessageId`. `leaseToken` защищает владельца. `sendStartedAt` обозначает начатую попытку и неопределённый исход; сам по себе не доказывает доставку. При явном отказе Telegram 4xx маркер принятой попытки снимается.

Успех транзакционно фиксирует outbox, видимый feed и `User.lastSentAt`. Следующее состояние меняется только при совпадении pending и ревизии. После истечения аренды без начатого send запись может вернуться в planned; прежняя заготовка отвязывается и собирается заново с актуальными подстановками. Если send уже мог уйти, запись становится dropped с осторожным ожиданием; слепого повтора нет, токен позволяет учесть поздний известный успех. Абсолютно единственная внешняя отправка не обещается.
