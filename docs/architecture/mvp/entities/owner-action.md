# OwnerAction · [← сводка](../00-overview.md)

Журнал действий владельца (R-133).

**Связи:** → User
**Сценарии:** UC-89, UC-93 ([привязка](../use-cases.md))
**Модуль-владелец:** [analytics](../modules.md#analytics)

## Поля
| поле | тип | обязательное | откуда значение | кто пишет | в API |
|---|---|---|---|---|---|
| `action` | enum(phrase_add, phrase_toggle, paraphrase_generate, paraphrase_review, role_card_edit, package_edit, strikes_grant, strikes_revoke, stars_refund, settings_edit, support_ticket_status_changed) | да | вычисляется | модуль действия | админу |
| `targetUserId`, `targetId` | ref | нет | вычисляется | модуль действия | админу |
| `targetTelegramId` | int | нет | снимок пользователя или обращения | модуль действия | админу |
| `details` | object: числа, причина, ID результатов или переход статуса | нет | ввод владельца и результат действия | модуль действия | админу |
| `at` | date | да | момент действия; для локального события передаётся в payload | модуль действия | админу |

«В API»: владельцу — хозяину записи; админу — владельцу продукта.

## Инварианты
- записи только добавляются
- `paraphrase_generate`: одна запись на успешно сохранённую пачку; `targetId` — исходная фраза, `details = {count, generatedIds}`. Одобрение и отклонение вариантов остаются отдельным `paraphrase_review`.
- `support_ticket_status_changed`: `targetId` — обращение, `details = {from, to}`; снимок Telegram ID берётся из обращения. Повтор текущего статуса не создаёт события.
- Эти два действия публикуют локальные асинхронные события после успешной записи данных. Ошибка журнала не меняет результат действия; редкая потеря события при падении процесса допустима. Новых транзакций, постоянной очереди и восстановления событий нет (D10).
- Тексты фраз и обращений в новых событиях и `details` не копируются. Существующие финансовые записи журнала сохраняют прежний порядок записи.
