# TaskNotificationState

Одно устойчивое состояние расписания персонажа на пользователя. Модуль-владелец — `task-notifications`. Основание — [D6 и единое расписание](../task-notifications.md).

- `_id = userId`, `userId` — пользователь; встроенная уникальность `_id` исключает несколько состояний.
- `revision`, `dirty` — ревизия и необходимость пересчёта. Существенные события обновляют их вместе со своим основным изменением в транзакции. Обычные чтения не сбрасывают дату.
- `nextAt` — сохранённый следующий момент; при отсутствии задач может отсутствовать. Будущий `moodFrom` сохраняет пробуждение.
- `owner`, `leaseUntil` — ограниченная аренда планирования/отправки, завершение с проверкой владельца и ревизии.
- `pendingOutboxId` — единственное ожидающее сообщение. Новое событие отменяет старое ожидание; старый успешный send сохраняется фактом, но не стирает pending новой ревизии.
- `pauseUntil` — конец общей паузы.
- `series` — идентификатор, исходный feed, остаток дополнительных обращений, признак штрафа исходной проверки и срок окончания. Источник серии также сохраняется в outbox, поэтому ключ единственного штрафа не теряется после завершения серии.

Индексы: `{dirty:1,nextAt:1}` и `{nextAt:1}`. Последнее успешное время отправки остаётся в `User.lastSentAt`. История не накапливается массивом: факты лежат в outbox. При удалении аккаунта состояние удаляется. В REST API эта сущность не выдаётся.
