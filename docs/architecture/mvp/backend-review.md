# Независимое ревью бэкенда MVP

Дата: 2026-10-24. Ветка: feat/mvp-api. Проверка выполнена защищённой ролью code-review по правилам MindFlow. Ниже сохранён итоговый отчёт ревьюера. Исправления и тестирование после этого отчёта не запускались: пользователь решил сначала разобрать замечания.

Найдено 7 подтверждённых дефектов.

1. **P1 — удалённые задачи могут заблокировать обработку дедлайнов остальных пользователей.**
   [deadline-sweeper.service.ts:14](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/tasks/services/deadline-sweeper.service.ts:14)
   Удаление задачи оставляет её период `active`. Sweeper выбирает первые 200 просроченных периодов и пропускает удалённые задачи, не меняя периоды и не продвигая выборку. После накопления 200 таких записей с ранними дедлайнами последующие периоды постоянно остаются за пределами выборки: провалы, штрафы и открытие следующих периодов перестают обрабатываться.

2. **P2 — просроченный период можно завершить успешно или продлить до обработки воркером.**
   [periods.service.ts:37](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/tasks/services/periods.service.ts:37)
   Проверяется сохранённый статус, но не наступление `deadline`. Если воркер задержался или был остановлен, запрос `completion` после срока начислит положительное уважение вместо провала; `extension` также может перенести уже прошедший срок. Нарушаются R-31/R-43 и применение переходов по времени дедлайна из N-4.

3. **P2 — открытие Mini App не учитывается как активность из-за глобального префикса.**
   [user-activity.interceptor.ts:14](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/users/interceptors/user-activity.interceptor.ts:14)
   В рабочем приложении `request.route.path` содержит `/api/me`, а сравнение выполняется с `/me`. Поэтому пользователь, открывший Mini App через `GET /api/me` без мутаций, не получает отметку посещения и первого старта. Искажаются D7, число активных пользователей и время до первой задачи; `lastActivityAt` тоже не обновляется. По той же причине проверка исключения `/owner/` ошибочно считает мутации владельца пользовательской активностью.

4. **P2 — следующая страница обращений поддержки всегда отклоняется.**
   [pagination.ts:8](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/common/utils/pagination.ts:8)
   `/paysupport` создаёт ID вида `telegram:123:456`, а `tickets()` возвращает его в `nextCursor`. Декодер запрещает двоеточие. При двух обращениях запрос с `limit=1` успешно выдаёт курсор, но следующий запрос с этим курсором получает 400. Просмотреть обращения за первой страницей невозможно.

5. **P2 — сортированная пагинация фраз пропускает начальные фразы пула.**
   [phrases.service.ts:36](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/phrases/phrases.service.ts:36)
   Курсор имеет формат `значение_ID`, но разбирается через `split('_')` с использованием только второго элемента. Начальные ID содержат подчёркивания, например `seed-mother-on_vague-0-any-4`. При `sort=-shows` или `sort=avg` ID обрезается до `seed-mother-on`, после чего условие следующей страницы исключает ещё не показанные фразы с тем же значением сортировки.

6. **P2 — бот не отправляет реакцию на ответ проверки.**
   [bot.service.ts:97](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/bot/bot.service.ts:97)
   После нажатия «Частично» или «Не начинал» `DeliveryService.answer()` возвращает `reply` из `on_check_in_reply`, но обработчик отбрасывает результат и только подтверждает callback. Пользователь не получает немедленную реакцию, требуемую R-50 и описанную в фактическом контракте. Для соседней ветки кнопок периода отправка `result.reply` реализована.

7. **P2 — сжатие контекста обслуживает только первые 100 диалогов.**
   [turn-recovery.service.ts:16](/Users/nikitakolchanov/programs/angry-dad/.claude/worktrees/feat-mvp-api/apps/api/src/modules/battle/services/turn-recovery.service.ts:16)
   Выборка ограничена 100 диалогами без пагинации и без исключения уже обработанных. Если первые 100 диалогов не имеют активного хода, они выбираются повторно даже при короткой истории. У следующих диалогов история никогда не сжимается; каждый новый ход загружает и передаёт актёру весь накопленный контекст, увеличивая объём запроса и расходы.
