# Фактический HTTP-контракт

По решению D9 от 2026-10-24 источником контракта являются реальные NestJS-контроллеры, DTO и метаданные `@nestjs/swagger`. Прежний YAML был проектным наброском. Его ручное редактирование больше не является способом изменения API.

## Экспорт

Обычный запуск API автоматически экспортирует контракт перед стартом через npm lifecycle scripts `prestart`, `prestart:dev` и `prestart:debug`. Например, из корня проекта:

```sh
npm run start:dev -w api
```

Те же команды из `apps/api` выполняют тот же экспорт. Если генерация не удалась, запуск останавливается. Экспорт выполняется один раз перед командой запуска; отдельная перекомпиляция в режиме watch контракт не обновляет. `start:prod` и worker автоматический экспорт не выполняют.

Для отдельного экспорта без запуска приложения, в том числе после изменений при уже работающем watch:

```sh
npm run generate:openapi
```

Команда собирает API с компиляторным плагином Swagger и сохраняет два артефакта на прежних местах:

- `docs/openapi.yaml`;
- `docs/openapi.json`.

Оба файла получаются из одного объекта Swagger, со стабильным порядком ключей. Текущий формат — OpenAPI 3.0; nullable-поля описаны через `nullable`, а обязательность отдельно через `required`. Сервер `/api`, пути без повторного префикса. На момент перехода — 51 HTTP-операция. Сгенерированные YAML/JSON вручную не правятся.

Проверка соответствия сохранённых файлов коду, без их перезаписи:

```sh
npm run check:openapi
```

Она включена в общий `npm run check`. При рассинхронизации возвращает ошибку с инструкцией повторного экспорта. Скрипт расположен в `scripts/docs/generate-openapi.mjs`; путь сохранения задан там явно.

Экспорт запускает только сканирование метаданных реального `AppModule` в Nest preview. Внутренний флаг `OPENAPI_EXPORT=1` устанавливается скриптом до импорта API, поэтому `.env` не загружается. `init`/`listen`, конструкторы обычных провайдеров, подключение к MongoDB, seed, worker и внешние клиенты не запускаются. Это генерация контракта, не сценарная проверка приложения.

Типы и код фронтенда в эту команду не входят. Фронтенд самостоятельно использует полученный YAML/JSON; существующая `npm run generate:api` для типов оставлена отдельной командой. `check:api` тоже осталась прежней проверкой актуальности типов фронта: после нового экспорта она может быть красной, пока фронт не пересоберёт свои артефакты.

## Где менять описание

- Контроллеры задают реальные маршруты, `operationId`, DTO и допустимые статусы ответов через Swagger-декораторы. Новые контроллеры автоматически попадают в сканирование графа модулей приложения; отдельного списка маршрутов для экспорта нет.
- DTO и Swagger-плагин дают поля, required/nullable, типы, enum, ограничения, форматы и параметры запросов. Изменение только текста Swagger не меняет runtime-валидацию.
- `apps/api/src/openapi/create-openapi-document.ts` задаёт общую конфигурацию документа, Telegram security schemes, `application/problem+json`, базовый путь и нормализацию имён схем без суффикса `Dto` с проверкой коллизий.
- `apps/api/src/openapi/problem.dto.ts` описывает публичную форму ошибки, включая `reply`, `errors` и `periodStatus`.
- `apps/api/src/openapi/response-metadata.ts` содержит общие описания ключей повторов и `Location`.
- `apps/api/src/openapi/operation-descriptions.ts` хранит перенесённые в код пояснения поведения. Генератор не читает прежний YAML как скрытый источник схем или описаний.

Swagger не выводит все возможные исключения из тела сервисов: новый ожидаемый HTTP-статус нужно описывать у операции. При этом сборка документа централизованно добавляет общую форму Problem к объявленным ошибкам, 400 для валидируемого ввода и 500 для неожиданной ошибки фильтра.

Фильтр `GET /owner/journal` и enum ответа включают `paraphrase_generate` и `support_ticket_status_changed`; описание `details` задаёт `count/generatedIds` и `from/to` соответственно. Новых маршрутов для этих событий нет.

## Исправленные повторы и конфликты

Повторный 200 с прежним телом явно описан для `createInvoice`, `createOwnerStrikeOperation` и `createBattleQuote`; первое создание остаётся 201. `Location` описан там, где его действительно устанавливает контроллер, включая эти повторы.

409 `role_mismatch` добавлен к `getBattleDialog`, `listBattleMessages`, `createBattleQuote` и `createShare` для боя. Счёт с тем же ключом и другим пакетом, цитата с тем же ключом и другим сообщением теперь возвращают 409 `idempotency_key_reused` вместо общего 400.

Ключ хода боя обязателен; ключи счёта, ручных операций и цитат необязательны. Для финансовых необязательных ключей срок 24 часа; для цитаты — пока хранится соответствующая реплика. Создание задач ключа повтора не имеет. Сами платежи/удары и их защита от двойного исполнения не менялись.

## Уведомления

`task-notifications` и совместимый `pressure` не содержат HTTP-контроллеров: расписание выполняет worker. Публичные операции уже находятся в delivery и включены в экспорт:

- `GET /feed`;
- `PUT /feed/{feedMessageId}/rating`;
- `PUT /feed/{feedMessageId}/check-in-answer`.

Telegram использует `POST /telegram/webhook` со своим секретным заголовком; Mini App Authorization на него не распространяется. Внутреннее состояние расписания наружу не публикуется.

## Проверка

При реализации выполнены статические сборка, lint/typecheck и генерация/сверка OpenAPI. Ревью, сценарные проверки HTTP, приложение и реальные интеграции не запускались по решению пользователя. Материал будущему тестеру — [передача бэкенда](../../testing/mvp-backend-handoff.md).
