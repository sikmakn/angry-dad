# Внешние сервисы · [← сводка](00-overview.md)

## Telegram Bot API
**Зачем:** сообщения персонажа с кнопками, приём команд и нажатий через вебхук, подтверждение пользователя Mini App по `initData`, подготовленное сообщение для шеринга (`savePreparedInlineMessage` и `shareMessage` в Mini App), события блокировки бота.
**Тестовый режим:** есть — тестовая среда Telegram (отдельный бот у @BotFather тестового сервера) и локально подставной клиент.
**Ограничения:** около 30 сообщений в секунду на бота и 1 в секунду на чат; ответ 429 с `retry_after`; заблокированный пользователь даёт 403.
**В тестах:** подставной клиент Bot API, записывающий исходящие сообщения; вебхук вызывается тестом напрямую с подписанным телом.
**Риски:** ⚠ упор в лимиты при совпадении проверок у многих пользователей — ограничитель скорости в delivery и откладывание (N-7); ⚠ кнопка под пересланным сообщением — сверка `from.id`.

## Telegram Stars
**Зачем:** продажа пакетов ударов: счёт в валюте XTR, `pre_checkout_query` (ответить за 10 с), `successful_payment` с `telegram_payment_charge_id`, возврат `refundStarPayment`.
**Тестовый режим:** есть — платежи Stars в тестовой среде Telegram без реальных Stars (N-15).
**Ограничения:** подтверждение может прийти повторно; возврат только целым платежом; вывод Stars — через Fragment, из Беларуси не ясно (Q-1 ТЗ).
**В тестах:** подставной платёжный шлюз за тем же интерфейсом, что и Telegram; сценарии двойного подтверждения и сбоя начисления.
**Риски:** ⚠ Q-1 ТЗ: если вывод невозможен, меняется монетизация, а не архитектура: платёжный провайдер — отдельный интерфейс в payments; ⚠ потеря `successful_payment` при простое — Telegram повторяет доставку вебхука, плюс дозачисление воркером.

## Провайдер ИИ
**Зачем:** пять задач с разными моделями: проверка конкретности и размер задачи (лёгкая, 3 с), судья (структура, до 2 повторов), актёр (жёсткий тон, 1–3 предложения), сжатие диалога (фон), перефразы для владельца.
**Тестовый режим:** частичный — у провайдеров нет бесплатной песочницы; в тестах и разработке подставной провайдер с заданными ответами, реальный включается настройкой.
**Ограничения:** платно по токенам (N-14: не больше 30% выручки с удара); таймауты; отказы по политике провайдера (Q-2 ТЗ: не больше 10% на 50 жёстких ходах); лимиты запросов в минуту при 100 одновременных ходах (N-6).
**В тестах:** подставной провайдер: валидный ответ, невалидный судья, таймаут, отказ по политике, инъекция в реплике.
**Риски:** ⚠ провайдер не выбран (Q-2 ТЗ) — интерфейс шлюза и выбор модели на задачу задаются настройкой; ⚠ отказы ломают ход — ход откатывается с возвратом удара, отказ пишется в `AiCall` для метрики; ⚠ в запрос не попадают Telegram ID, username и имя (N-11).
