# HTTP и кеш

Источник HTTP-схем — [OpenAPI](../../openapi.yaml); соответствие сценариям — [карта контракта](../../architecture/mvp/contract-map.md). [operations.ts](../../../apps/web/src/api/operations.ts) связывает операции с маршрутами, [client.ts](../../../apps/web/src/api/client.ts) кодирует path/query, JSON и Telegram Authorization. DTO и enum здесь не дублируются.

Транспорт ограничивает запрос 40 секундами, объединяет timeout с отменой caller и обрабатывает 204 без JSON. Автоматических транспортных повторов нет. `Problem.reply` сохраняется, остальные ошибки отображаются через `errorText`; сетевой сбой означает неизвестный результат записи, а не доказанный отказ сервера.

По [useApi](../../../apps/web/src/hooks/useApi.ts) ключ чтения — `[scope, operation, path, query]`. Для сессии используется scope `session`, для данных пользователя — его ID. `useRead` считает данные свежими 15 секунд; выбранные экраны опрашиваются раз в 3 секунды. `usePages` использует cursor, размер страницы 100 и свежесть 10 секунд. Обновление при инвалидации, повторном показе или polling не является автоматическим повтором неудавшейся записи.

`useWrite` блокирует повторный вызов до завершения текущего, отключает retry и после завершения инвалидирует scope пользователя и профиль сессии. QueryClient также отключает retry запросов и мутаций. Кеш находится в памяти; общей записи кеша на диск нет. Особый guard создания задачи использует sessionStorage отдельно.

Профиль опрашивается каждые 3 секунды. Страница задачи и её проверка, диалог боя и баланс также используют polling; лента с пагинацией обновляется по событиям/инвалидации. Кнопки повтора чтения дают пользователю явную попытку. Смена сессии и удаление аккаунта очищают данные по правилам [App](../../../apps/web/src/App.tsx).

Сервер остаётся источником статусов, размера, уважения, баланса, фраз и результатов боя. Демо fixtures и тестовые ответы не подтверждают исполнение этих правил настоящим сервером.
