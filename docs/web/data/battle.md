# Ход, баланс и окна Telegram

Сценарии определены [F-11](../../specs/mvp/functions/F-11-battle-dialog.md), [F-12](../../specs/mvp/functions/F-12-battle-turn.md), [F-13](../../specs/mvp/functions/F-13-payments.md), [F-14](../../specs/mvp/functions/F-14-sharing.md); HTTP-схемы — в [OpenAPI](../../openapi.yaml).

## Неизвестный исход хода

[useBattle](../../../apps/web/src/battle/hooks/useBattle.ts) читает диалог, страницы сообщений и баланс в scope пользователя; роль входит в path ключа. Диалог и баланс опрашиваются раз в 3 секунды. Когда `turnInProgress` становится false, сообщения перечитываются, в том числе если сервер завершил ход между опросами.

Перед первой отправкой создаётся UUID `Idempotency-Key` и снимок текста. При сетевом сбое или неопределённом ответе ручная проверка отправляет ту же пару key/body. Это повтор той же операции, а не новая реплика. Пока сервер сообщает обработку, отправка блокируется. `turn_failed` и определённый отказ 4xx, кроме `turn_in_progress`, завершают попытку; текст остаётся для новой отправки с новым ключом. Автоматических повторов записи нет.

Попытка хранится в ref смонтированного экрана: после reload или ухода с него ключ не восстанавливается. Нужно проверить обновлённый диалог и баланс перед новой репликой. Серверная гарантия идемпотентности должна быть подтверждена при интеграции, двойник её не доказывает.

## Покупка

[usePurchase](../../../apps/web/src/shop/hooks/usePurchase.ts) запрашивает invoice и вызывает `openInvoice` только в Telegram версии не ниже 6.1 и вне MSW. Callback не зачисляет удары на клиенте: UI ждёт роста серверного баланса, опрашивает его, затем инвалидирует историю операций. Через минуту ожидания появляется совет обновить баланс и обратиться к `/paysupport`. Новую оплату во время ожидания не предлагают; cancel/failed позволяют повторить вручную.

Магазин в шторке боя сохраняет смонтированный бой и его черновик. Реальные Stars, webhook, возвраты и доставка уведомлений в текущем этапе не подтверждены.

## Отправка карточки

[useShare](../../../apps/web/src/sharing/hooks/useShare.ts) требует Telegram не ниже 8.0, `shareMessage` и выключенные моки. Серверный prepared ID передаётся платформе; выбор чата, отмена и успех обрабатываются callback. Изображение в web не рисуется: API не отдаёт preview. Обезличивание и реальный вид изображения требуют проверки серверной интеграции. См. [расхождение](../../limitations/contract.md).
