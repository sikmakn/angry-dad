# Данные задач и восстановление отправки

[useTaskForm](../../../apps/web/src/tasks/hooks/useTaskForm.ts) создаёт задачу через `createTask`, [useTaskActions](../../../apps/web/src/tasks/hooks/useTaskActions.ts) меняет задачу/период и отвечает на проверки. Схемы задаёт [OpenAPI](../../openapi.yaml); исходные правила — [F-3](../../specs/mvp/functions/F-3-task-create.md), [F-4](../../specs/mvp/functions/F-4-one-time-task.md), [F-5](../../specs/mvp/functions/F-5-recurring-task.md), [F-6](../../specs/mvp/functions/F-6-check-ins.md).

Чтения задач, периодов и проверок используют общий ключ с ID пользователя, operation, path и query: [механика кеша](api.md). Главная автоматически дочитывает активные страницы; закрытые и остановленные запрашиваются при открытии архива и имеют отдельные кнопки пагинации.

Успешный ответ изменения периода/задачи сразу помещает задачу в ключ `getTask`, затем выполняется инвалидация. Поэтому следующий GET с ошибкой не отменяет известный успешный результат. Фраза и точная дельта последнего действия хранятся локально в состоянии экрана; ограничения reload описаны [отдельно](../../limitations/contract.md).

## Неизвестный исход POST

До отправки создания [taskSubmissionRecovery](../../../apps/web/src/tasks/taskSubmissionRecovery.ts) сохраняет название и расписание по пользователю в sessionStorage, с резервом в памяти. Ключ `angry-dad:task-submission:<userId>` не является серверной идемпотентностью. При недоступном storage резерв переживает переход между экранами, но не гарантирует восстановление после reload.

Успех очищает guard. Явный отказ HTTP ниже 500 или `ai_unavailable` также снимает его, сохраняя поля формы. Потерянный ответ, timeout и другие неопределённые сбои блокируют новый POST, включая возвращение на форму и reload при доступном sessionStorage.

«Обновить список задач» вручную читает все страницы списка. После успешного чтения пользователь проверяет задачи, ставит подтверждение и выбирает «Вернуться к форме без отправки». Только это снимает guard; само действие не создаёт задачу. Если сохранённая задача найдена, её можно открыть. Отсутствие в списке не является строгим доказательством того, что первый POST не завершится позже.

Фронт сейчас не отправляет ключ идемпотентности при создании задачи. Расхождение с текущим main-контрактом и незавершённым backend отмечено в [ограничениях](../../limitations/contract.md); документация не вводит новое решение.
