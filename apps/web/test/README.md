## Браузерный слой

`browser/mvp.spec.ts` содержит семь независимых тестов в настоящем headless Google Chrome (`channel: chrome`), один worker, один браузер, без retries:

- Onboarding → первая задача → серверный onTaskSet → главная → закрытие → ответ/изменение уважения.
- Архив closed/stopped → карточка закрытой задачи → reload с сохранением маршрута → Telegram Back → главная/архив.
- Сервер сохранил задачу, но ответ POST потерян: reload сохраняет черновик и guard, список показывает сохранённую задачу, явное подтверждение снимает блокировку без второго POST.
- Same-session activated: обновление профиля сохраняет маршрут, открытую форму и черновик без POST создания задачи.
- Native dialog: исходный фокус, Tab/Shift+Tab через границы, inert фон, Escape и Telegram Back возвращают фокус opener; следующий Back возвращает на главную.
- Два отдельных мобильных теста: **390×844** и **320×844**, длинное название, отсутствие горизонтального overflow после загрузки шрифтов, доступность формы/кнопки и диалога, фактическая тёмная тема Telegram вопреки светлой теме ОС, смена темы событием, геометрия верхней/боковых/нижней safe area и изменение нижнего inset событием.

`browser/fixtures.ts` создаёт для каждого теста собственный профиль, задачи и счётчики запросов; Playwright создаёт новый context/storage. API заменён управляемыми route handlers, ответы типизированы по frozen OpenAPI, **настоящий продуктовый HTTP-клиент** сохранён. Проверяется Authorization от Telegram double. Неизвестные API/внешние HTTP-запросы блокируются и проваливают проверку; необработанные ошибки страницы также проваливают её. Telegram double установлен через addInitScript до загрузки продукта, официальный SDK URL перехвачен; платёжные/внешние Telegram методы не выполняют живых вызовов.

`playwright.config.ts` управляет единственным Vite webServer через `npm run test:browser:server`, `http://127.0.0.1:4179`, `reuseExistingServer: false`. `vite.test.config.ts`: `envDir: false`, `publicDir: false`, React plugin, `VITE_USE_MOCKS='false'`, `VITE_API_BASE_URL='/api'`, без proxy. Service workers заблокированы. Продуктовые MSW fixtures/worker не участвуют. Зависимости и scripts подготовлены координатором, эта роль их не меняла и браузеры не скачивала.

Координатор выполнил этот browser набор с разрешением слушать loopback и запускать установленный Chrome; итог — 7 passed, как указано выше. Обходов hook/sandbox не было.

## Окружение и границы результата

Базовый режим: Vitest + RTL + user-event + **настоящий HTTP-клиент** и MSW на уровне fetch. Fixtures проверяются TypeScript по generated типам frozen OpenAPI. Хуки и проверяемые алгоритмы не подменены. MSW использует `onUnhandledFrame: 'error'`, чтобы незаданные запросы не уходили в сеть.

Расширенный режим выполнен координатором по прямому запросу. Первоначальный EPERM на bind порта и отсутствие Playwright/scripts — только история; последующий результат — 7 passed. Самостоятельный dev-server не запускался; сервером распоряжается только Playwright runner с `reuseExistingServer: false`. DOM shim базового режима по-прежнему не доказывает браузерную доступность.

Настоящего E2E с API/MongoDB нет: Docker, существующий API, БД, .env и секреты не использовались. API и Telegram заменены двойниками; нет живых Telegram/Stars/ИИ вызовов. MSW закрывается после каждого файла; RTL cleanup, QueryClient и sessionStorage очищаются. Browser context/routes/storage уничтожаются раннером после каждого теста; webServer завершается раннером. Контейнеров нет, очистка чужого окружения не нужна. Артефакты Playwright и исторические failure traces остаются только в gitignored `test/.browser-results`; HTML report не включён.

Проверены выбранные сценарии в одном установленном Chrome и двух мобильных ширинах (390 и 320), не полное WCAG, не все 14 экранов и не реальные Stars. Отложенные вопросы share preview API, восстановления onSuccess, lastExtendedOn и bot/legal config не решались тестами. Не заявляется полное покрытие владельца, платежей, шеринга, всех серверных правил или всего фронтенда.
